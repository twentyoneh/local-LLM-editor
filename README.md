# Локальный редактор документов

Настольное приложение на Java и JavaFX для обработки DOCX, ODT и TXT с помощью локальных LLM.

В главном окне можно открыть документ, выбрать действие и сравнить исходный текст с результатом. Внизу отображаются прогресс обработки и состояние подключения к моделям.

![Главное окно редактора с выбором действия, исходным текстом и результатом](<docs/ui интерфейс .png>)

## Возможности

- Исправление ошибок, упрощение и продолжение текста.
- Добавление действий через JSON-файлы в `actions/`.
- Проверка формы ответа и проверка другой локальной моделью.
- Ручная оценка результата: доработка по замечанию пользователя.
- Ограниченные повторные генерации, прогресс и отмена обработки.
- Сохранение нового документа в DOCX, ODT или TXT без перезаписи исходника.

Первая версия сохраняет текст и абзацы. Сложная вёрстка, таблицы, изображения и сноски автоматически не переносятся; при обнаружении неподдерживаемых элементов приложение предупреждает об ограничениях.

## Требования

- JDK 21 или новее.
- Локальный сервер с OpenAI-совместимым API, например Ollama.
- Интернет при первой сборке для загрузки Maven и Java-библиотек.

Maven отдельно устанавливать не нужно: в проект включён Maven Wrapper. Maven и зависимости сохраняются в стандартном пользовательском каталоге `.m2`, за пределами исходников проекта.

## Запуск

Из папки проекта на macOS или Linux:

```sh
./mvnw javafx:run
```

На Windows:

```powershell
.\mvnw.cmd javafx:run
```

На macOS также можно дважды нажать `run.command`. Для работы в IDE откройте `pom.xml` как Maven-проект и выберите установленный JDK. При необходимости задайте `JAVA_HOME`.

## Настройка LLM

Конфигурация находится в `config/config.properties`. Основные параметры также доступны в окне «Настройки»:

```properties
generation.baseUrl=http://localhost:11434/v1
generation.model=qwen2.5:3b
verification.mode=BOTH
verification.baseUrl=http://localhost:11434/v1
verification.model=gemma3:4b
processing.maxRegenerationRetries=3
```

Модели должны быть доступны на локальном сервере. Для их загрузки в Ollama:

```sh
ollama pull qwen2.5:3b
ollama pull gemma3:4b
```

В режиме `BOTH` после проверки формы ответ оценивает другая модель. В режиме `FORM_ONLY` выполняется только проверка формы; смысловая правильность текста не проверяется второй LLM. При недоступности checker приложение не отключает его автоматически. Кнопка «Проверить подключение» проверяет наличие настроенных моделей через `/v1/models`.

Для checker запрос содержит `response_format={"type":"json_object"}`: локальный сервер должен поддерживать [JSON-режим OpenAI-совместимого API](https://docs.ollama.com/capabilities/structured-outputs) (Ollama поддерживает его). Ответ дополнительно проверяется программой: `valid` должен быть boolean, `reason` — строкой. Генератор возвращает обычный текст. Если ответ checker обрывается по лимиту, увеличьте `verification.maxOutputTokens`.

Окно «Настройки» позволяет указать URL и названия моделей, выбрать режим проверки и задать число повторных генераций.

![Настройки генератора Qwen, проверяющей модели Gemma, режима проверки и лимита повторов](<docs/настройки редактора.png>)

## Работа с документом

1. Откройте DOCX, ODT или TXT. Для TXT при необходимости выберите кодировку.
2. Выберите действие и нажмите «Обработать».
3. Дождитесь проверенного результата или отмените обработку.
4. Если результат не устраивает, нажмите «Доработать результат…», опишите замечание и нажмите «Доработать». Например: «Не сокращай названия разделов, сохрани все числа».
5. Нажмите «Сохранить как». По умолчанию выбран формат исходника; доступны все три формата.

Ручная доработка дополняет автоматические проверки. Генератор получает исходный текст, предыдущий ответ (`previousResult`) и замечание (`userFeedback`). В режиме `BOTH` проверяющая модель получает те же данные и оценивает новый ответ с учётом замечания. В `FORM_ONLY` выполнение замечания оценивает пользователь. Промпты действия остаются в `actions/*.json`, инструкции и данные для доработки собираются в `PromptFactory`, запуск — в `ProcessingService.revise`.

При «Продолжении» дорабатывается только ранее созданное продолжение: оно заменяется новым, исходник остаётся в документе ровно один раз. При ошибке или отмене доработки предыдущий результат остаётся доступен для сохранения. Каждая ручная доработка получает собственный бюджет автоматических повторов из конфигурации; последующее замечание применяется к последнему принятому результату, история замечаний отдельно не передаётся.

Доработка отправляет исходник и предыдущий ответ целиком, без разбиения или обрезания. Если они вместе с замечанием превышают контекст или лимит ответа модели, приложение сообщает об этом и сохраняет предыдущий результат. Для больших документов нужны соответствующие `contextWindowTokens` и `maxOutputTokens` в настройках моделей.

`maxRegenerationRetries=3` разрешает три повтора после первоначальной генерации. Бюджет общий на весь документ. При повторе используется исходный текст и причина отклонения. Сетевые ошибки завершают задачу без скрытых повторных генераций. Оценка второй моделью снижает вероятность ошибок, но не гарантирует абсолютную правильность результата.

### Исправление ошибок

Выберите «Исправление ошибок» и нажмите «Обработать». Слева остаётся исходный текст с ошибками, справа появляется результат, прошедший автоматические проверки.

![Пример исправления орфографических ошибок: исходник слева и результат справа](<docs/Пример исправления ошибок.png>)

### Упрощение текста

Действие «Упрощение» помогает сократить сложные формулировки. На примере ниже объём текста уменьшился с 890 до 604 знаков.

![Результат упрощения текста об использовании электронного календаря](<docs/упрощение текста.png>)

### Доработка по замечанию пользователя

Если результат нужно уточнить, нажмите «Доработать результат…» и опишите требуемые изменения. В этом примере пользователь просит удалить абзац о сборе обратной связи после тестового периода.

![Окно ввода замечания с просьбой удалить ненужный абзац](<docs/пример промпта для доработки результата.png>)

После успешной доработки справа отображается новый вариант без указанного абзаца. В строке состояния показано завершение доработки; объём результата в примере составляет 424 знака.

![Упрощённый текст после доработки: указанный пользователем абзац удалён](<docs/урощение после доработки .png>)

### Продолжение текста

Выберите «Продолжение», чтобы добавить новый фрагмент к исходному документу. Справа отображается исходный текст вместе с созданным продолжением.

![Пример продолжения рассказа о смотрителе маяка](<docs/пример продолжения текста .png>)

### Сохранение результата

Нажмите «Сохранить как…», укажите имя нового файла и выберите формат: DOCX, ODT или TXT. На скриншоте открыт список доступных форматов.

![Диалог сохранения результата с выбором DOCX, ODT или TXT](<docs/сохранить как .png>)

## Действия и промпты

Файлы `actions/*.json` содержат название действия, режим `REPLACE` или `APPEND`, `generationPrompt`, `verificationPrompt` и `formRules`. Для нового обычного действия добавьте JSON с уникальным `id`. После изменения перечитайте настройки через их сохранение в приложении или перезапустите программу.

## Сборка и тесты

```sh
./mvnw test
./mvnw package
```

Тесты используют временные документы и тестовый HTTP-сервер; установленная LLM им не требуется. После сборки JAR и библиотеки находятся в `target/`:

```sh
java -jar target/local-llm-editor-1.0.0.jar
```

Для сборки macOS-приложения со встроенной Java:

```sh
./scripts/package-macos.sh
```

Результат появится в `dist/LocalDoc-macos-arm64/` или `dist/LocalDoc-macos-x86_64/`. Переносите весь каталог: приложение использует лежащие рядом `config/` и `actions/`.

## Структура проекта

```text
src/main/   код приложения и оформление окна
src/test/   автоматические тесты
config/     внешняя конфигурация
actions/    действия, промпты и правила проверки
scripts/    запуск и упаковка приложения
.mvn/       настройки Maven Wrapper
docs/       фотографии и скриншоты работы программы
pom.xml     зависимости и настройки сборки
```
